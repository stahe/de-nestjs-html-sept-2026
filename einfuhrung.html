    Dieses Dokument ist ein Produkt der KI Claude von Anthropic. Sein Ziel ist es, das Dokument *Einführung in ASP.NET MVC anhand von Beispielen* (2013) an das Web-Framework [NestJS] anzupassen:

    • das Framework [ASP.NET MVC] und die Sprache [C#] werden durch das Framework [NestJS] und die Sprache [TypeScript] ersetzt;
    • die [Razor]-Views werden durch [Handlebars]-Views ersetzt;
    • [Entity Framework] wird beim Datenzugriff durch einen ORM, [TypeORM], und eine [MySQL]-Datenbank ersetzt.

    Das Dokument folgt der Struktur des ursprünglichen Kurses: zunächst zahlreiche kleine Projekte, die sich jeweils auf ein einziges Konzept konzentrieren, gefolgt von einer umfassenden Fallstudie – einer Webanwendung zur Terminplanung in einer Arztpraxis – mit durchgehend kommentierten Dateien. Das Kapitel des ursprünglichen Kurses zu den Grundlagen der Webprogrammierung (das HTTP-Protokoll, die Sprache HTML) wurde nicht übernommen: Diese Grundlagen werden als bekannt vorausgesetzt.

    1.1. Die Rolle von NestJS in einer Webanwendung

    Eine Webanwendung wird häufig in Schichten aufgebaut, wobei jede Schicht nur mit den benachbarten Schichten kommuniziert:

    • die Web-Schicht empfängt die HTTP-Anfragen des Browsers und liefert ihm HTML-Seiten zurück. [NestJS] unterstützt uns beim Schreiben dieser Schicht;
    • die Geschäftsschicht enthält die Geschäftsregeln der Anwendung (z. B. „Ein Patient darf nur einen anstehenden Termin haben“). Sie weiß nichts vom Web: Sie könnte ebenso gut eine Kommandozeilenanwendung bedienen;
    • die Datenzugriffsschicht ([DAO]-Schicht, von [Data Access Object]) liest aus der Datenbank und schreibt in sie. Wir verwenden den ORM [TypeORM] ([Object Relational Mapper]), der die Zeilen der Tabellen auf [TypeScript]-Objekte abbildet.

    Die Web-Schicht selbst folgt dem [MVC] -Modell ([Model – View – Controller]):

    • der Controller (C) ist eine Klasse, deren Methoden – Actions genannt – jeweils einen bestimmten Anfragetyp bearbeiten (zum Beispiel [GET /schedule]). Eine Action liest die Anfrageparameter, ruft die Geschäftsschicht auf und wählt anschließend die anzuzeigende View aus;
    • das Modell (M) ist die Menge der Daten, die die Action an die View übergibt: ein einfaches [JavaScript]-Objekt;
    • die View (V) ist eine [Handlebars]-Datei (Erweiterung [.hbs]): eine HTML-Datei, in der [{{...}}]-Tags durch Daten aus dem Modell ersetzt werden.

    Die Verarbeitung einer Anfrage folgt den nummerierten Schritten im Diagramm:

    • 1: Der Browser sendet eine HTTP-Anfrage, zum Beispiel [GET /schedule?doctorId=1&day=2026-09-24];
    • 2: [NestJS], das auf dem Webserver [Express] aufbaut, wählt die Action aus, die für diese Anfrage zuständig ist: Das ist das Routing. Bevor die Anfrage dort ankommt, kann sie durch Middleware, Guards, Interceptors und Pipes laufen, die wir in den folgenden Kapiteln untersuchen;
    • 3: Die Action fordert die benötigten Daten von der Geschäftsschicht an;
    • 4: Sie erstellt das Modell für die View und gibt an, welche View es anzeigen soll;
    • 5: Die View-Engine [Handlebars] erzeugt die HTML-Seite, die [NestJS] an den Browser zurückliefert.

    [NestJS] ist ein [Node.js]-Framework, das in [TypeScript] geschrieben ist. Es baut auf den Konzepten der Frameworks [Spring] ([Java]) und [Angular] auf: Dekoratoren ([@Controller], [@Get], [@Injectable]...) beschreiben die Rolle jeder Klasse, und die Dependency Injection versorgt jedes Objekt mit den Abhängigkeiten, die es benötigt. Es wird häufig verwendet, um Server zu schreiben, die JSON an einen [JavaScript]-Client ([Angular], [React], [Flutter]...) liefern. Dieses Dokument verwendet es, um eine klassische Webanwendung zu schreiben: Der Server erzeugt die HTML-Seiten, und der Browser zeigt sie lediglich an.

    1.2. Verwendete Werkzeuge

    Die Beispiele wurden mit den folgenden Werkzeugen geschrieben und getestet (ihre Installation ist im Anhang beschrieben):

    • [Node.js] 20 und sein Paketmanager [npm];
    • der Editor [Visual Studio Code];
    • ein aktueller Browser ([Chrome], [Firefox], [Edge]);
    • das Kommandozeilenwerkzeug [curl], das rohe HTTP-Antworten anzeigt (es ist in [Windows] 10 und 11 enthalten);
    • das DBMS [MySQL] (oder [MariaDB]), zum Beispiel das von [Laragon] unter [Windows], ab dem Kapitel zum Datenzugriff.

    Die Bibliotheksversionen sind die in der Datei [package.json] im Beispielordner: [NestJS] 10, [TypeScript] 5, [hbs] 4 ([Handlebars]), [class-validator] 0.14, [TypeORM] 0.3, [Bootstrap] 5.

    Um ein Beispiel auszuführen, öffnen Sie eine Konsole im

    und geben Sie ein:

    npx nest start

    [npx] findet das Werkzeug [nest] im Ordner [node_modules] des übergeordneten Ordners. [nest start] kompiliert den [TypeScript] -Code in den Ordner [dist] und führt dann [dist/main.js] aus. Mit der Option [--watch] wird der Code neu kompiliert und der Server neu gestartet, sobald eine [.ts]-Datei geändert wird:

    npx nest start --watch

    Alle Beispiele lauschen auf Port 3000: Es kann immer nur eines gleichzeitig laufen. Beenden Sie den Server in der Konsole mit [Ctrl-C].

    • Zeile 12: Der Compiler meldet die Verwendung eines Werts, der [null] oder [undefined] sein kann;
    • Zeile 13: Deklarationsdateien von Bibliotheken werden nicht geprüft (schnellere Kompilierung).

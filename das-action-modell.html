    3. Das Action-Modell

    Eine Action benötigt Informationen, die der Browser sendet: die URL-Parameter ([?name=martin&age=42]), Formularfelder und Routenparameter. Der ursprüngliche Kurs bezeichnet all diese Informationen als das Modell der Action. Dieses Kapitel zeigt, wie [NestJS] es der Action bereitstellt, es in den richtigen Typ umwandelt und validiert.

    import { Controller, DefaultValuePipe, Get, ParseIntPipe, Query } from '@nestjs/common';

@Controller('parameters')
export class ParametersController {
  // /parameters/action01?name=martin
  @Get('action01')
  action01(@Query('name') name: string): string {
    return `name = [${name}], of type ${typeof name}`;
  }

  // /parameters/action02?age=42: ein Parameter ist IMMER ein String
  @Get('action02')
  action02(@Query('age') age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action03?age=42: ParseIntPipe konvertiert (oder lehnt ab)
  @Get('action03')
  action03(@Query('age', ParseIntPipe) age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action04?page=2: ein Standardwert, falls der Parameter fehlt
  @Get('action04')
  action04(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number): string {
    return `page = [${page}], of type ${typeof page}`;
  }

  // /parameters/action05?name=martin&age=42: alle Parameter auf einmal
  @Get('action05')
  action05(@Query() parameters: Record<string, string>): object {
    return parameters;
  }
}

    Gehen wir diesen Code im Einzelnen durch:

    • Zeilen 6–9: [@Query('name')] injiziert den Wert des Parameters [name] aus der URL (der Teil nach [?], die Query-String oder [query string] genannt);
    • Zeilen 12–15: Der Parameter [age] ist mit dem Typ [number] deklariert ... doch dieser Typ ist lediglich eine [TypeScript]-Deklaration, die zur Kompilierzeit entfernt wird. Wir erhalten immer einen String, wie die Ausführung zeigt;
    • Zeilen 18–21: [ParseIntPipe] ist eine Pipe: ein Objekt, das den Wert eines Parameters umwandelt (und validiert), bevor er die Action erreicht. Hier wird der String ['42'] zur Zahl 42; ein nicht numerischer String führt zu einem 400-Fehler (Bad Request), ohne dass die Action ausgeführt wird;
    • Zeilen 24–27: Die Pipes werden verkettet: [DefaultValuePipe(1)] ersetzt einen fehlenden Parameter durch 1, anschließend wandelt [ParseIntPipe] ihn um;
    • Zeilen 30–33: [@Query()], ohne Argumente, injiziert ein Objekt, das alle Parameter der URL enthält.

    Die Anführungszeichen um die URL sind notwendig, wenn sie das Zeichen [&] enthält, das für die Konsole eine besondere Bedeutung hat. Beachten Sie Folgendes:

    • Ein fehlender Parameter wird als [undefined] behandelt;
    • Ein vorhandener Parameter ist unabhängig vom deklarierten Typ ein String;
    • Eine Pipe dient dazu, einen Parameter umzuwandeln und zu validieren, und liefert den Statuscode 400, wenn der Wert ungültig ist.

    3.2. Beispiel 08: Ein durch eine Klasse beschriebenes Action-Modell

    Hat eine Action mehrere Parameter, werden sie durch eine Klasse beschrieben, die oft [DTO] ([Data Transfer Object]) genannt wird. Jedes Feld der Klasse hat Validierungsdekoratoren aus der Bibliothek [class-validator]. Diese entsprechen den Attributen [[Required]], [[Range]] usw. von [ASP.NET MVC].

    import { Type } from 'class-transformer';
import { IsEmail, IsIn, IsInt, IsNotEmpty, IsOptional, Length, Max, Min } from 'class-validator';

export class PersonDto {
  @IsNotEmpty({ message: 'the name is required' })
  @Length(2, 20, { message: 'the name must have 2 to 20 characters' })
  name: string;

  @Type(() => Number)
  @IsInt({ message: 'the age must be an integer' })
  @Min(0, { message: 'the age must be positive' })
  @Max(150, { message: 'the age cannot exceed 150' })
  age: number;

  @IsIn(['Mr', 'Mme', 'Melle'], { message: 'unknown title' })
  title: string;

  @IsOptional()
  @IsEmail({}, { message: 'invalid email address' })
  email?: string;
}

    Gehen wir diesen Code im Einzelnen durch:

    • Zeile 1: [@Type] stammt aus der Bibliothek [class-transformer], die die empfangenen Daten umwandelt;
    • Zeile 2: die Validierungsdekoratoren aus [class-validator];
    • Zeilen 5–7: Der Name ist erforderlich ([@IsNotEmpty]) und muss zwischen 2 und 20 Zeichen lang sein ([@Length]). Jeder Dekorator akzeptiert eine eigene Fehlermeldung;
    • Zeilen 9–13: [@Type(() => Number)] verlangt, dass der empfangene String vor der Validierung in eine Zahl umgewandelt wird: eine ganze Zahl ([@IsInt]) zwischen 0 und 150 ([@Min], [@Max]);
    • Zeilen 15–16: Die Anrede muss einer der Werte einer Liste sein;
    • Zeilen 18–20: Die E-Mail-Adresse ist optional ([@IsOptional]); falls vorhanden, muss sie gültig sein ([@IsEmail]).

    import { Controller, Get, Query } from '@nestjs/common';
import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // /persons/action01?name=martin&age=42&title=Mr
  @Get('action01')
  action01(@Query() person: PersonDto): object {
    return {

      ageType: typeof person.age,

    import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  // automatische Validierung ALLER Action-Modelle, die durch eine Klasse beschrieben sind
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true, // konvertiert die empfangenen Strings in die deklarierten Typen
      whitelist: true, // entfernt die in der Klasse nicht deklarierten Felder
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

    • Zeile 10: [transform: true]: Die Action erhält eine echte Instanz von [PersonDto], deren Felder umgewandelt wurden ([@Type]);
    • Zeile 11: [whitelist: true]: Parameter, die keinem Feld der Klasse entsprechen, werden entfernt.

    import { Controller, Get, Query } from '@nestjs/common';
import { plainToInstance } from 'class-transformer';
import { validate } from 'class-validator';
import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // keine ValidationPipe hier: die Action erhält die ROHEN Parameter und
  // entscheidet selbst, wie sie mit den Fehlern umgeht
  @Get('action01')
  async action01(@Query() raw: Record<string, string>): Promise<string> {
    // 1. rohes Objekt -> PersonDto-Instanz (inklusive @Type-Konvertierungen)
    const person = plainToInstance(PersonDto, raw);
    // 2. Prüfung der Constraints (@IsNotEmpty, @Min ...)
    const errors = await validate(person);
    // 3. in beiden Fällen eine HTML-Seite: kein 400-Fehler
    if (errors.length === 0) {
      return `<p>Welcome ${person.title} ${person.name} (${person.age} years old)</p>`;
    }
    const items = errors
      .map((e) => `<li>${e.property}: ${Object.values(e.constraints ?? {}).join(', ')}</li>`)
      .join('');
    return `<p>The form contains errors:</p><ul>${items}</ul>`;
  }
}

    Kommentieren wir diesen Code:

    • Zeile 11: Die Action erhält die rohen Parameter: ein Objekt, dessen Felder alle Strings sind;
    • Zeile 13: [plainToInstance] ([class-transformer]) erzeugt aus dem rohen Objekt eine Instanz von [PersonDto] und wendet dabei die Umwandlungen an ([@Type]);
    • Zeile 15: [validate] ([class-validator]) prüft alle Einschränkungen. Es gibt ein Array mit Fehlern zurück, das leer ist, wenn alles in Ordnung ist. Jeder Fehler nennt das betroffene Feld ([property]) und die Meldungen der verletzten Einschränkungen ([constraints]);
    • Zeilen 17–18: keine Fehler – eine Willkommensseite;
    • Zeilen 20–23: andernfalls eine Seite, die die Fehler auflistet. In beiden Fällen ist die Antwort eine HTML-Seite mit dem Statuscode 200.

    Dies ist die Technik, die alle Formulare der Fallstudie verwenden werden (siehe Beispiel 19).

import { ArrayMinSize, IsArray, IsIn } from 'class-validator';

export class ChoiceDto {

    import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

// wandelt ein französisches Datum "23/09/2026" in ein ISO-Datum "2026-09-23" um
@Injectable()
export class DateFrPipe implements PipeTransform<string, string> {
  transform(value: string): string {
    const m = /^(\d{2})\/(\d{2})\/(\d{4})$/.exec(value ?? '');
    if (!m) {
      throw new BadRequestException(`[${value}] is not a date in the dd/mm/yyyy format`);
    }
    const [, day, month, year] = m;
    const iso = `${year}-${month}-${day}`;
    // "31/02/2026" hat die richtige Form, existiert aber nicht
    if (new Date(`${iso}T00:00:00Z`).toISOString().slice(0, 10) !== iso) {
      throw new BadRequestException(`the date [${value}] does not exist`);
    }
    return iso;
  }
}
    • Zeilen 4–5: Eine Pipe ist eine Klasse mit [@Injectable()] , die das Interface [PipeTransform<input, output>] implementiert;
    • Zeile 6: Ihre Methode [transform] erhält den Wert des Parameters und gibt den umgewandelten Wert zurück, den die Action empfängt;
    • Zeilen 7–9: Ein Wert, der nicht die Form [dd/mm/yyyy] hat, löst eine [BadRequestException] (400) aus;
    • Zeilen 13–15: Ein Datum, das im richtigen Format vorliegt, aber nicht existiert (31/02/2026), wird ebenfalls abgelehnt: [new Date] „korrigiert“ es auf den 03/03/2026, was erkannt wird.

    import { createParamDecorator, ExecutionContext } from '@nestjs/common';
import { Request } from 'express';

// @Language(): die bevorzugte Sprache des Browsers, aus dem Header gelesen
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
export const Language = createParamDecorator((fallback: string | undefined, ctx: ExecutionContext): string => {
  const req = ctx.switchToHttp().getRequest<Request>();
  const header = req.get('accept-language') ?? '';
  const first = header.split(',')[0].trim().slice(0, 2).toLowerCase();
  return first || fallback || 'fr';
});
    • Zeile 6: [createParamDecorator] erzeugt einen Parameterdekorator, ähnlich wie [@Query] oder [@Body]. Die Funktion erhält das Argument des Dekorators ([@Language('fr')]) und den Ausführungskontext der Anfrage;
    • Zeile 7: Der Kontext ermöglicht den Zugriff auf die [Express]-Anfrage;
    • Zeilen 8–10: Es werden die ersten zwei Buchstaben des Headers [Accept-Language] zurückgegeben, der die bevorzugten Sprachen des Benutzers angibt.

    3.6.4. Fazit

    Das Action-Modell wird von [NestJS] anhand der Anfrage erzeugt: Routenparameter ([@Param]), URL ([@Query]), der Rumpf ([@Body]) und Header ([@Headers]). Die Pipes wandeln diese Werte um und validieren sie. Bei einer HTML-Anwendung ist es meist vorzuziehen, das Modell selbst zu validieren (Beispiel 09), damit Sie das Formular erneut anzeigen können. Das ist das Thema des nächsten Kapitels.
